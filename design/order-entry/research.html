Kerosene / Design research / 27 September 2026

A clearer order ticket, at every pane size.

Keep Kerosene’s direct trading controls and compact terminal character. Strengthen the reading order: market → order type → price and size → execution options → review → submit.

Research and layout proposal only. Current behavior was checked against the order-entry source and the bundled README screenshot; the running application was not captured.

What should change in Kerosene

Current implementationProposed improvement
The whole form scrolls, including submit buttons, presets, and feedback.Keep submission and status in a fixed footer. Scroll only the inputs and optional controls. Reflow price/size and the summary into columns in short, wide panes. The bundled screenshot exposes this need: only the top of the ticket fits in its bottom-right pane.
A large outlined symbol badge; a small combined leverage badge; “Avail” and “Used” on a separate row.Use a quiet, compact context header. Keep the symbol, market type, margin mode, and leverage together. Make available funds readable. Move used margin to secondary details and expose the active account alias without a wallet address.
Separate Price and Size headings, a detached Mid button, and a small COIN/USD denomination toggle.Put persistent labels and explicit units inside the fields. Show HYPE/BTC rather than generic COIN, the actual quote currency for price, and the existing converted amount just below size. Keep Mid adjacent to price.
The percentage slider is as tall as an input, with unlabeled clickable quarter marks.Use a thin track with a generous hit area and visible 25/50/75/100% labels. Preserve the existing sizing behavior and show the selected percentage. This improves discoverability without adding more controls.
Notional conversion sits in the size heading; maker/taker estimates form a tiny centered sentence.Group order value and fees into aligned label/value rows. Preserve maker/taker uncertainty for ordinary limits; use a taker estimate for market orders. A future margin or liquidation estimate needs a correct Hyperliquid calculation before appearing here.
Reduce Only and IOC appear together; Market, Limit, Chase, and TWAP are equally accessible.Keep all four order types directly accessible. Replace IOC’s checkbox presentation with an explicit GTC/IOC time-in-force control for limits. Show slippage for market orders. Expand algorithm-specific fields only when selected.
Presets expand below submission and directly execute Buy/Sell orders.Label that section “Quick trade presets.” Keep execution presets distinct from size selectors. Put errors and account-readiness reasons next to the stable action buttons; retain side labels while pending.

Suggested first pass

Implement the header, input grouping, labeled percentage track, explicit GTC/IOC selector, fee summary, responsive arrangement, and fixed action/status footer. Preserve existing submission snapshots, sizing rules, account validation, and all four order types.

For spot and outcome contracts, retain their market-specific labels and restrictions. Use Buy/Sell for spot, contract units for outcomes, and hide leverage controls where inapplicable. Percentage sizing must retain the current side-specific balance checks. Hyperliquid position effects should drive action wording; Bybit/Binance hedge-mode Open/Close tabs should not be copied without matching semantics.

Later feature work: attached TP/SL, a standard post-only option, and margin/liquidation previews. These need order lifecycle or calculation work; they are not cosmetic additions to the first pass.
